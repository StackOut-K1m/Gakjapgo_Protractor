# 동의 없이도 감지가 돌아간다 — 온보딩 동의가 강제되지 않음

| | |
|---|---|
| 영역 | 온보딩 (BE) · 자세 감지 (AI) — **스터디룸 담당 아님** |
| 심각도 | 높음 — 카메라 영상 기반 기능이라 동의가 법적 근거다 |
| 발견 | 2026-08-03, 코드 확인 |
| 상태 | ⛔ 미수정 · 담당자 확인 필요 |

## 무엇이 문제인가

동의 값을 **받아서 저장은 하는데, 쓰는 쪽이 아무도 확인하지 않는다.**

### 1. 미동의로 온보딩을 마칠 수 있다

`OnboardingSaveRequest`의 동의 필드는 `@NotNull`이다.

```java
@NotNull(message = "자세 감지 동의 여부는 필수입니다.")
@NotNull(message = "졸음 감지 동의 여부는 필수입니다.")
```

`@NotNull`은 **"값이 있어야 한다"**이지 **"true여야 한다"**가 아니다. `false`를 보내면
그대로 통과하고 온보딩이 완료된다. `@AssertTrue`가 필요한 자리에 `@NotNull`이 들어가 있다.

세 번째 항목(`posture_capture_consent`)은 아예 선택이다. 미전송 시 `false`로 저장된다.

### 2. 감지 API가 동의를 확인하지 않는다

`domain/posture` 전체에서 `MemberPreference`를 읽는 곳이 **0건**이다.

```bash
grep -rn "Preference\|Consent" domain/posture/   # 결과 없음
```

즉 `posture_detection_consent = false`인 회원도 자세 판정 요청이 그대로 처리된다.
`drowsiness_detection_consent`도 마찬가지다.

동의를 **철회해도** 달라지는 게 없다. 온보딩 수정 API 주석에 "동의는 false로 철회 가능"이라고
적혀 있지만, 철회한 뒤에도 감지는 계속 돈다.

## 왜 문제인가

`MemberPreference` 주석에 이렇게 적혀 있다.

> 동의 항목은 법적 근거가 되는 값이라 변경 시각(consent_updated_at)을 따로 남긴다.

변경 시각까지 남길 만큼 **법적 근거로 다루기로 한 값**인데, 정작 그 값이 동작을 바꾸지 않는다.
기록만 남고 강제는 없는 상태다.

카메라 영상에서 신체 랜드마크를 추출하는 기능이라 "동의를 받았다"는 기록이 실제 동작과
어긋나면 기록 자체가 의미를 잃는다.

## 어디를 고쳐야 하나

**둘 다 고쳐야 한다.** 한쪽만 고치면 구멍이 남는다.

| # | 작업 | 위치 | 비고 |
|---|---|---|---|
| 1 | 필수 동의는 `@AssertTrue`로 | `OnboardingSaveRequest` | 미동의로 온보딩 완료를 막는다 |
| 2 | 감지 요청 시 동의 확인 | `domain/posture` 서비스 | 미동의면 403 |
| 3 | 철회 시 진행 중 세션 처리 | 미정 | 즉시 중단인지, 다음 세션부터인지 |

**1번만 하면 부족하다.** 온보딩 이전에 만들어진 회원과 철회한 회원이 남는다.
**2번만 하면** 온보딩에서 막히지 않아 사용자가 나중에 403을 만난다.

3번은 정책 결정이 필요하다. 공부 중에 마이페이지에서 동의를 끄면 그 세션의 자세 판정을
어떻게 할지 정해야 한다.

## 확인이 필요한 것

- **어느 항목이 필수인가.** 자세 감지 없이 이 서비스가 성립하는지에 따라 다르다. 감지가
  핵심이라면 자세 감지는 필수, 졸음·캡처는 선택으로 나누는 편이 자연스럽다.
- **미동의 회원에게 무엇을 보여줄 것인가.** 감지만 끄고 스터디룸은 쓰게 할지, 아예 막을지.
  전자라면 스터디룸(내 담당)에서 자세 판정 없이 도는 경로가 필요하다.

## 담당

온보딩·회원은 **내 담당이 아니다.** 자세 감지도 AI 담당 영역이다.
스터디룸 쪽 영향은 위 "미동의 회원에게 무엇을 보여줄 것인가"가 정해진 뒤에 붙인다.
