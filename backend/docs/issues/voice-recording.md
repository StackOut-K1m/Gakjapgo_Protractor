# 음성 녹음 — 저장할 곳이 없다

| | |
|---|---|
| 영역 | 스터디룸 (BE) — 설계 결정 4와 같은 건 |
| 심각도 | 중간 — 기능 미완성. 지금 깨지는 것은 없다 |
| 발견 | 2026-08-03, 스키마 확인 |
| 상태 | ⏳ 팀 확정 대기 — 임의 구현 금지 |

## 무엇이 문제인가

**정본 스키마에 음성·녹음 관련 테이블도 컬럼도 없다.**

```bash
grep -inE "voice|녹음" schema.sql   # 결과 없음
```

그런데 화면과 기능명세에는 존재한다.

- 기능명세에 `FR-VOICE` 항목이 있다
- 프론트에 `VoiceConsentPage.tsx`가 있고, 스터디룸 입장 전 **음성 동의서**를 받는다
- 최근 머지(`fix/study-room-create-edit`)에서 상세 페이지에 음성 동의 흐름이 연결됐다

즉 **동의는 받는데 그 동의를 저장할 곳도, 동의 대상인 녹음 기능도 없다.**

## 지금 상태

| | 상태 |
|---|---|
| 음성 동의 화면 | ✅ 있음 (프론트) |
| 동의 저장 API | ❌ 없음 |
| 동의 저장 컬럼 | ❌ 없음 |
| 녹음 기능 | ❌ 없음 |
| 녹음 파일 테이블 | ❌ 없음 |

동의를 받고 나서 **어디에도 남기지 않고 버린다.** 새로고침하면 다시 묻는다.

## 설계 결정 4와 같은 문제다

`DESIGN_DECISIONS.md` 결정 4에 이미 적혀 있는 항목이다.

> 정본 스키마에 `whiteboard`/`files`/`voice` 관련 테이블 **부재**. 기능명세엔 FR-COLB/FR-VOICE 존재.
> 저장·조회(REST)는 테이블이 정해져야 가능. 팀 우선순위 미정으로 보류.

화이트보드는 결국 **이번 버전에서 빼는 것으로 정리했다**(2026-08-05, 결정 4). 음성은 그 정리도
안 된 상태다 — 화면만 있고 뒤가 비어 있다.

## 정해야 할 것

**① 이번 프로젝트에서 녹음을 하는가.**

이게 먼저다. 안 한다면 나머지는 볼 필요가 없고, 프론트의 음성 동의 화면을 빼는 것으로 끝난다.
지금처럼 동의만 받고 아무것도 안 하는 상태가 제일 나쁘다 — 사용자는 녹음된다고 생각한다.

**② 한다면, 무엇을 저장하는가.**

| 선택지 | 필요한 것 |
|---|---|
| 동의 여부만 | `member_preferences`에 컬럼 하나. 가장 가볍다 |
| 동의 + 녹음 파일 | 테이블 신규 + 파일 저장소 + 보관 기간 정책 |

②를 고르면 게시판 첨부(`post_attachments`)가 이미 파일 저장 방식을 만들어 뒀으니 그 구조를
참고할 수 있다.

**③ 보관 기간과 삭제.**

음성은 개인정보라 무기한 보관하면 안 된다. 언제 지우는지 정해야 하고, 그건 기능이 아니라
정책이라 팀 합의가 필요하다.

## 권장

**①에서 "안 한다"로 정리하는 쪽을 권한다.**

- 남은 일정에서 녹음 저장·재생·보관 정책까지 붙이기는 부담이 크다
- 개인정보라 어설프게 넣으면 문제가 커진다
- 화이트보드는 같은 고민 끝에 아예 빼는 쪽으로 정리했고, 빼고 나서 문제가 생기지 않았다

정리한다면 프론트의 음성 동의 화면을 빼거나, **"이번 버전에서는 녹음하지 않습니다"**로
문구를 바꾸면 된다. 동의를 받는 화면이 남아 있는데 기능이 없는 상태가 가장 오해를 부른다.

## 담당

스터디룸 소속이라 **내 담당이 맞다.** 다만 결정 4와 마찬가지로 **팀이 정해야 착수할 수 있다.**
정해지기 전까지 임의로 테이블을 만들지 않는다.
