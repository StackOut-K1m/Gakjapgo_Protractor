# 빌드 · 배포 매뉴얼 — 각잡고(Protractor)

## 0. 서비스 개요

웹캠 기반 온라인 스터디룸 서비스. 자세 감지·집중도 측정·화상 스터디·AI 리포트를 제공.

- **운영(main)**: `https://gakjapgo.site`
- **테스트(develop)**: `https://i15c106.p.ssafy.io`
- 단일 호스트(AWS **Lightsail**)에서 운영/테스트 2환경을 Docker Compose로 병행 구동.

전체 컨테이너: `nginx`(리버스프록시·TLS) · `backend`/`backend-prod`(Spring Boot) · `frontend`/`frontend-prod`(React 정적, nginx 서빙) · `mysql` · `redis` · `openvidu`(OpenVidu Server + KMS) · `jenkins`(CI/CD) · `dd-agent`(Datadog). 모두 외부 네트워크 `protractor-net` 에 연결.

## 2. 빌드 방법

### 2-1. 백엔드 (Spring Boot / Gradle)
- 빌드 산출물: `backend/build/libs/*.jar`
- 도커 멀티스테이지(`backend/Dockerfile`)에서 Gradle 빌드 → JRE 21 런타임 이미지 생성.
- 이미지에 **Datadog Java 트레이서**(`dd-java-agent.jar`)를 다운로드해 `JAVA_OPTS`의 `-javaagent`로 부착(APM용).
```bash
docker build -t protractor-backend:<tag> ./backend
```

### 2-2. 프론트엔드 (React / Vite)
- `frontend/Dockerfile`: Node 22에서 `npm run build`(=`tsc -b && vite build`) → 정적 산출물을 nginx 이미지로 서빙.
- **Datadog RUM 값은 빌드 시점 주입**(Vite는 `VITE_*`를 번들에 박음). build-arg로 전달:
```bash
docker build \
  --build-arg VITE_DD_RUM_APP_ID=3ef01d23-62f5-4dfc-90a5-a5372c318b93 \
  --build-arg VITE_DD_RUM_CLIENT_TOKEN=pub5ab2bc6be03310368795b538a6dd1bc2 \
  --build-arg VITE_DD_SITE=ap1.datadoghq.com \
  -t protractor-frontend:<tag> ./frontend
```

## 4. 배포 방법

### 4-1. 사전 준비 (호스트)
```bash
docker network create protractor-net                       # 최초 1회
# 업로드 영속 디렉터리 (backend 실행 uid=999 소유)
sudo mkdir -p /srv/protractor/prod/uploads/{posts,profile-images}
sudo chown -R 999:999 /srv/protractor/prod/uploads
# 시크릿 파일 배치 (chmod 600): ~/app/backend-secrets-prod.env  (3장 값)
# TLS 인증서: /etc/letsencrypt/live/gakjapgo.site/ (certbot 발급)
```

### 4-2. 인프라·앱 구동 (Docker Compose)
- 인프라(nginx·mysql·redis·openvidu·jenkins)는 `~/app/docker-compose.yml`로 구동.
- DB 스키마는 `protractor_prod_dump.sql` import (아래 6장).
```bash
cd ~/app
docker compose -p app up -d nginx mysql redis openvidu jenkins
docker compose -p app up -d --force-recreate backend-prod frontend-prod
```

### 4-3. CI/CD (Jenkins)
- **테스트(develop)**: GitLab push 웹훅 → `app-pipeline` 자동 빌드 → `:latest` 이미지 → `backend`/`frontend` 배포.
- **운영(main)**: 수동 잡 `prod-deploy` (파라미터 `VERSION`, 예 `v1.3.0`). `refs/tags/${VERSION}` 체크아웃 → 버전 태그 이미지 빌드(프론트는 RUM build-arg 주입) → `docker-compose.yml + docker-compose.datadog.yml` 병합으로 `backend-prod`/`frontend-prod` 재생성 → 버전 이미지 5개 보관.
- **릴리스 흐름**: develop에서 `git tag vX.Y.Z` → main 병합 → `prod-deploy VERSION=vX.Y.Z` 실행.
- **롤백**: `prod-deploy`를 이전 버전으로 재실행.

## 5. 배포 특이사항

- **AWS Lightsail**(EC2 아님): 인스턴스 IAM 역할로 S3 접근이 안 되어, **S3는 IAM 유저 액세스 키**(`AWS_ACCESS_KEY_ID/SECRET`)로 접근.
- **OpenVidu(방향 B)**: openvidu-dev를 내부 4443(HTTP)로 두고 **엣지 nginx가 443 TLS 종단** 후 `/openvidu`·`/dashboard` 프록시. `FORCE_PLAIN_HTTP=false`로 wss 네이티브. KMS는 `KMS_EXTERNAL_ADDRESS`(공인 IP)로 ICE 광고.
- **미디어 UDP 포트**: `8000-8199/udp`(200개, SRTP) 공개. 방 인원·화면공유 스트림 수에 맞춰 산정(서버 측 미디어 flow ≈ N²).
- **STOMP WebSocket**: nginx `/ws` → backend 8080 (wss↔ws 종단).
- **운영/테스트 격리**: DB 분리(`protractor`/`protractor_prod`) · Redis 인덱스 분리(0/1) · 업로드 경로 분리(`/srv/protractor/{uploads,prod/uploads}`). OpenVidu·nginx·mysql·redis·jenkins는 **공유**.
- **포트 보안**: MySQL 3306은 `127.0.0.1` 바인딩(외부 차단, SSH 터널로만 접근). Jenkins 9090은 웹훅용으로 노출.
- **TLS 인증서**: `gakjapgo.site`(+www) Let's Encrypt. 수동(standalone) 발급이라 **자동 갱신 없음** — 만료 전 갱신 필요.
- **업로드 영속**: 호스트 bind mount라 컨테이너 재배포에도 파일 유지. (향후 S3 이전 여지)

## 6. DB 적용 (덤프 import)
```bash
# 대상 DB·유저 생성 후
docker exec -i <mysql-container> sh -c 'mysql -uroot -p<root_pw> protractor_prod' < protractor_prod_dump.sql
```
- 덤프: `protractor_prod_dump.sql` — **전체 스키마(21개 테이블)** + **정제된 시드 데이터**. `CREATE DATABASE` 미포함이라 대상 DB를 먼저 만들고 import.
- **정제(개인정보 제거) 내용**:
  - `members`: 실사용자 데이터를 제거하고 **샘플 계정 5개**만 유지 — `admin`(ADMIN) + `user1~4`(MEMBER), provider `LOCAL`.
    - 로그인 계정: `admin@admin.com`, `user1@user.com` ~ `user4@user.com`
    - 비밀번호는 bcrypt 해시로 설정되어 **로그인 가능**합니다. (평문 비밀번호는 Mattermost `@newnbnet` 문의)
  - **마스터/참조 테이블**(`study_tags`, `stretchings`) 데이터는 유지.
  - 그 외 사용자 데이터 테이블(친구·DM·게시글·학습기록·리포트·일정 등)은 **비움**(스키마만 유지).
